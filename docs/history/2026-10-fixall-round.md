# 2026-10 修复轮（历史记录）

2026-10-25 维护者要求把当时已知、还没修的缺陷一个一个修完（「一个一个修，全部修」），在分支 `fix/open-defects-20261025`（起点 main `6947e94`）上进行。范围是 2026-10-18 质量轮「仍未解决」的全部条目、issue #1 #2 #4 #7、示范录屏的复查与文档项；维护者另外勾选了跨缩放统一重建与任意嵌套滚动（原本 `docs/ARCHITECTURE.md` §九写明不做），#5 断点续算与 #11 浏览器扩展列为后续，跨缩放只做比例、不做旋转。这一轮在当天收尾时停止，下面记录做完的、撤回的和还没做的。

## 方法

每一项先写在起点上失败的合成场景或 Rust 测试，再改 Rust 核心；每个改动都跑 `deno task test`、三种构建的 parity 与场景、场景指纹对起点，以及 32 段真实录屏的成对 A/B（同一段录屏两个原生 CLI 同时跑，比画布、诊断、像素与耗时），每一段有像素变化的都看过裁图。出现新的鬼影、撕裂、洞或烙印就不交，改动存成 patch。修复由几个并行的 track 在各自的 worktree 里完成，逐个合进整合分支。

## 采用的改动

### 解码（浏览器外壳）

- **WebKit 把 B 帧按解码顺序交回**：示范录屏加上 `-bf 3` 后 Playwright WebKit 有 76 次时间倒退，Chrome 与原生解码都正确；32 段真实录屏的重排深度都是 2。demux 遍历样本表时记下 `reorderDepth`，`PreciseSource` 用这么深的有序缓冲放出最早的帧。新 fixture `tests/fixtures/bframes-pyramid.mp4`，顺序测试改成 Chrome 与 WebKit 都跑。
- **Chrome 156 拒收每段 iPhone HEVC 录屏的第一个关键包**（「marked as type key but wasn't a key frame」）：Apple 的编码器把 SEI 写在访问单元分隔符（AUD）前面，而 H.265 要求 AUD 是访问单元的第一个 NAL。HEVC 关键包现在把 AUD 移到最前、不丢字节。只有 worker 里的完整流程会触发，页面主线程直接解码不会，所以原来的浏览器解码测试没有发现。
- **DECODER_STALLED 误报**：卡住的计时改为从流水线真的开始等待空队列才起算；之前流水线在一帧上同步工作超过超时时间，下一帧就会被误判为解码器卡住。test_4 那次卡住在 Chrome 156 上跑两次没有重现。

### 区域学习与吸顶遮挡

- **部分时间出现的粘性目录（new_mac_3）**：学习器给出候选二维块（不碰区域上下缘、不宽过一半、高至少三分之一），求解端逐帧判断「页面运动解释不了这块」才遮挡；判断用位姿相对上一次放置的实际移动，不用里程计步长（锚点重捕的步长 0 不是停顿）。长图里的目录残字与淡字都消失。
- **一帧里有页面行在静止行之上就不给吸顶带**；**判断「站着不动」时连同取样点左右邻居一起比**（取样点落在 1 px 笔画旁的白色上时，白对白的差是 0，曾让 factor 4 的反向路径丢掉 776 个像素）。
- **左右带的走查可以跨过滚动条滑块到静止面板**（new_mac_4 的 minimap）。
- **投票走查可以跨过短缺口**：比值仍 ≥ 1.4 的行（new_ip_3 的底部玻璃栏，1.4 落在实测的 1.48 与 own_f 渐层 1.32 之间），或仍有固定物件的行（pub_6 的灵动岛）。
- **圆角卡片上缘**（new_ip_6、new_ip_7 的地图资讯卡）：原生边取整行变化最陡的一步。
- **区域时期**：区域矩形整段不变，从某一帧起可以多排除几块矩形；学习器能学出一次性收起的顶栏（issue #1，`toolbar-collapse` 场景改成严格断言）。底栏收起与反复收放没有做，真实录屏里也还没有这种情况。

### 求解

- **孤儿片段**：片段上丢失的帧重定位到另一张画布、而这一步的位移量到了时，记录接回；new_ip_6 模糊段的 142 帧因此接回主图。
- **整段接回的片段不再留下 0×0 的空画布**（画布清单、离线查看器、结果包里的「未定位片段 · 0×0」）。
- **奇数步长**：960 宽的帧按半尺寸分析时，奇数原生步长是半个分析像素，整数位移的误差变大、信心跌到零位移占位之下；未知运动改为看有匹配的最强假设（示范奇数步长版的 UNRESOLVED_MOTION 59 → 0）。

### 呈现画布与回弹

- **示范长图的透明边**：示范路径在页缘内弧形折返、停住，被读成弹簧回弹，白板同色留白被留空。现在两轴都静止、停在边外比停在边上多 8 次以上就撤回那条边；示范三种变体的透明像素都变成 0。示范的上边正好卡在门槛（8:0）。
- **Dock 条纹**：没有单一底色的行在延伸区留透明；与相邻已延伸行颜色连续的行照样延伸（map 的毛玻璃侧栏）。

### 其他

- 原生 CLI 可以输出与网页同格式的结果包（`--package`、`RunResult::write_package`、Python `write_package`），查看器模板只有一份。
- 原生预读线程（32 段耗时几何平均 0.81×）、HDR 颜色备忘加大、揭示格累加走对齐切片，输出逐字节不变。
- 场景的 `provisionalPixels` 改数最终瓦片里仍带瞬态位的像素（照 TESTING 的定义），各场景棘轮按新量法下调；`maxFixedConflicts` 新棘轮；新增与加强的合成场景（部分时间目录、滑块、玻璃高顶栏、带静止图标的玻璃栏与大标题、回弹、反向卡片、嵌套滚动量测）。
- issue #4（重复内容中途反向的周期别名）：原始重现条件与另 11 组变体的放置误差都是 0，`layers.test.ts` 的用例改回反向路径守护。
