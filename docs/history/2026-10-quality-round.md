# 2026-10 新录屏质量轮（历史记录）

> **历史文档。** 写于 `feat/quality-20261018` 完成时，基准是这批改动前的 main `c65e33e`。数字反映当时的状态，不是当前基线；现行规则以 [ARCHITECTURE.md](../ARCHITECTURE.md) §十 为准。文中的测量产物在作者本机 gitignored 的 `test-results/opt-20261018/`（`HANDOFF.md`、`tracks/<主题>/REPORT.md`、`gate-*/summary.md`、`verdict/VERDICT.md`），不在仓库里。索引见 [README.md](README.md)。

这一轮从 13 段新录屏出发（4 段 Mac、9 段 iPhone：Messages、ChatGPT 类聊天、X、LINUX DO、Google Maps 卫星图与矢量图、Bilibili、App Store），加上 8 段公开录屏、10 段作者的录屏和一段 Apple Maps，共 32 段。原算法在其中几段上拼得很差：屏幕固定的栏碎成几十到上百个片段，Google Maps 碎成 10–58 片，半透明的 iOS 26 玻璃栏在长图顶端留下透过玻璃看到的叠影。这里只留下以后还用得上的东西：根因、采用的做法、试过但排除的路线，以及还没解决的问题。

## 方法

- **原生命令行做 A/B。** `rust/long-screen` 的命令行用 AVFoundation 解码（iPhone 的 HEVC 也能读），与网页共用同一份 Rust 核心；同一段录屏两个二进制同时跑、同样的线程数，比较耗时、画布数、诊断计数，以及按画布 bounds 对齐后的像素差。负载很高时绝对耗时没有意义，只看成对的比值。录屏文件名里 macOS 在「AM/PM」前放的是 U+202F，不能手打。
- **独立真值。** 地图类录屏用 OpenCV（LK 光流 + similarity RANSAC，另做相位相关，排除顶底 UI）逐步算位移，再和引擎的位姿逐步比较；new_ip_7 的 522 步、new_ip_6 的 2937 步都是纯平移，只有 new_ip_6 最后 11 步是真缩放。
- **逐个看图。** 每一段有变化的画布都裁出原生分辨率的前后对照亲眼看；另有一轮独立的检查专门找「改后有而改前没有」的鬼影、撕裂、洞与烙印。

## 采用的改动

### 区域学习：屏幕固定的栏

- **合并后仍独立的运动区域，像素多半留在原地就是固定界面**（`regions/merge.rs::freeze_stationary_regions`）。iOS 大标题收合的头部（new_ip_1）、液态玻璃标签栏（new_ip_9，92% 的帧都在变）、YouTube 的顶栏与侧栏（new_mac_1，侧栏旁没有可见的边，带的找边停在浏览器自己的侧栏）都被切成了独立的运动区域，求解按每个状态开一个片段：5、134、5 个运动画布。学习器早就逐像素累加「留在原地比跟着页面走解释得好」与反过来的取样数，区域构建没用它；这三块留在原地分别是跟着走的 6.6、1.9、7.9 倍，所有主内容区与 `panes` 场景的两个 pane 都在 0.5 以下。凭多数决冻结，但区域自己要有可见的结构（结构取样分布在至少 3 行、3 列）：pub_2 对话区的空白边距只在与顶栏交界的一行有结构，不冻结。
- **变化检查找不到带的一侧，用逐行投票找带；再按固定物体的像素往里延伸。** 见 ARCHITECTURE §十「几何与分层」两条。new_ip_3 的低置信放置 233 → 0，顶端那块 120×325 的透明洞与 new_ip_2 的头像糊影都消失。

### 追踪：浮在内容上的屏幕固定界面

- **拆分残差救回与「重定位和救回矛盾就不用重定位」。** Google Maps 矢量图（new_ip_7）的状态栏、搜索栏、chips 在运动层里，每帧在零位移上对上：真实步长常被零位移取代，关键帧 patch 也取在这些界面上，main 上 130 次重定位没有一次对。对非零候选，每个取样点取「零位移的平均误差」与「候选的取样不敏感误差」中较小的一个再平均；同画布重定位与救回相差 ≥ 16 px 时用救回（和已有的锚点重捕规则同一条）。
- **移动区域里停在屏幕上的格子不参与配准**（`kernels/track/screen_fixed.rs`）。卫星图（new_ip_6）甩动时瓦片变糊（Laplacian 方差 120–590，全片中位数 1453），地图点几乎分不出位移，清楚的界面点每帧在零位移对上，上面两条救不回。求解时用区域自己量到的步长，逐 8×8 分析格投票「留在原地还是跟着走」，留下 ≥ 6 帧且 ≥ 4 倍跟随的格（外扩一格）不取里程计取样点、特征与关键帧 patch；区域里多数格都留下时不排除（那是嵌套 pane 自己在动）。输出、归属与持久化都不变。new_ip_6 与真值相差 ≤ 3 px 的步数 2897 → 2924／2926，0–2836 帧落在同一张图上；new_ip_7 522／522。

### 求解：以自己的小速度移动的吸顶头部

- **吸顶遮挡认小速度移动的顶带。** 见 ARCHITECTURE §十「几何与分层」。new_ip_8（Bilibili）长图里重复的标签栏消失。

### 揭示：低对比的尺寸动画

- **时刻排序的「带瞬态」改用投票同一把尺。** new_mac_2 的 Haiku 卡片随滚动放大，和页面每通道只差约 13；降级只看亮度离群格（48），佐证用 tau = 24，判「变化」却用 CHANGED = 8／SHIFTED = 3，于是最新一帧既不算带瞬态又算已佐证，被选为时刻，而分量的遮罩只到卡片外一点，卡片边缘沿 16 px 块边界切成三级台阶。现在上下文块与共识矛盾除了亮度离群，还包括 vote() 会判为变化、小相位解释不了、且静止段前一帧没显示同样差异的情况，并且只对平坦的共识块用这条低对比判据（第二版对所有共识块用，new_ip_6 的地名取到了正在淡入的一帧）。

### 性能

三项都只改非 SIMD 路径或加备忘，32 段输出逐位相同：SDR YUV 成对转换（一帧 2.9×）、HDR 平面路径每分块 4096 格色码备忘（3.0×）、合成器整行块统计（2.4×）。见 ARCHITECTURE §十二。

### 合成场景

新增 6 个场景，对应这一轮的缺陷家族：`large-title-collapse`、`glass-tab-bar`、`sticky-toc-later`、`hover-card-grow`、`map-pan-chips`、`header-lag-collapse`；验证器新增两种描述：动态区域可标 `atomic` 并用 `torn` 计数抓「由不同帧的行拼成的台阶」，`expect.unlearnedFixed` 列出已知学不成固定区域的覆盖物（学成了测试就失败，名单只会变短）。合成的玻璃栏与大标题栏没有真实录屏里「图标、文字留在原地」的投票结构，所以这几个场景还不能守住上面的区域修正（见「仍未解决」）。

| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 变化检查已找到的带，再按行投票往里延伸（Bilibili 的吸顶标签栏）                            | new_ip_8 的顶带 189 → 279、STICKY_OCCLUSION 333 → 1，但重复的标签栏还在：它是展开态头部压在已滚动的页面上，同一位置部分时间出现，固定带不能包含它；后来由吸顶遮挡的小速度判据修掉                                                                                                                                 |

## 仍未解决

- **卫星图探索边缘的界面烧入。** 只在搜索栏、chips、状态栏后面出现过的世界像素没有干净观察，合成器写进去的就是界面；卡片上缘 28 px（圆角露出地图让那几行的平均变化超过 0.9）在运动层里。可能的方向：求解结束后把整段录屏的排除矩形写进一个区域摘要行再对所有帧套用（要改 FORMAT.md）；被排除的像素只在没有其他观察时才写入；输出用的遮罩改成逐像素、不外扩。
- **own_a 的鬼影。** 不是流式回复重排：那是 Chrome 双指放大后的 ChatGPT 页面，一个运动区域里其实有侧栏与聊天栏两个独立滚动的 pane，只有窄窄的聊天栏在滚时位移被当成 0，之后五次都是 1635.0 px 的回环修正被拒，约 250 帧整段错位。方向：多次独立回环给出完全相同的偏移时接受，或把放大后的侧栏切成独立层。
- **new_ip_8 的轮播** 仍是两个时刻拼的（接缝换了位置）；锚点重捕的帧把步长 0 交给吸顶遮挡；揭示在「最好的完整时刻被遮挡」时怎么选，属于时刻排序加「黏在屏幕上」偏好的修法。
- **new_mac_3 的粘性目录**（只在 31% 的帧出现，下面是平坦页边，揭示的不透明判据 `frac > 0.3` 过不了）与 **new_mac_4 的 minimap**（右带的走查碰到滚动条滑块那一栏就停）：设计在 `tracks/sticky-2d/REPORT.md`，学习器出候选块、求解端逐帧遮挡；侧带走查跨过「会动但从不跟页面走」的窄栏。
- **own_c 的页首** 现在是固定画布（长图不变），区分「先跟着走再停」要逐格的纯跟随帧累加器（`tracks/bars-followups/REPORT.md`）。
- **合成场景** 的玻璃与大标题栏要加上静止的图标、文字纹理，`map-pan-chips` 可以换成能逐像素重现零位移吸附的强版本，再收紧 `limitation` 与 `unlearnedFixed`。
- **平台。** 只在 macOS 原生命令行做了 32 段的成对计时；Chrome 与 WebKit 只跑了浏览器测试套件。`pwa.test.ts` 的 WebKit 离线示例在机器有负载时会失败（页面被关掉），main 上同样会（各 5 次失败 2 次），不是这批改动造成的。
