# 能力边界：逐项对应原需求

“已验证”指有带真值的自动化测试断言，或在真实 Chrome 中实际跑通并检查过输出。

## 移动与轨迹

| 需求                                 | 状态   | 证据                                                                     |
| ------------------------------------ | ------ | ------------------------------------------------------------------------ |
| 上下左右、斜向、非单调二维移动       | 已验证 | `traversal` `diagonal` `horizontal`：位置误差 0，缺失 0，虚构 0          |
| 停止、回滚、反复查看                 | 已验证 | `revisit` 三次经过同一区域；`vertical` 含暂停与反向                      |
| 轻微手抖、非恒定速度                 | 已验证 | `vertical` `phone` 带抖动路径                                            |
| 高速 fling、内容只出现 1–2 帧        | 已验证 | `fling` `glimpse`：单帧可见内容仍进入结果                                |
| 同一内容只出现一次                   | 已验证 | 所有场景断言“虚构像素 = 0”且覆盖集合与观察视口并集相等                   |
| 薄重叠跳转                           | 部分   | 标记 `THIN_OVERLAP_STEP`；回访证据更强时改正并记录，此前像素可能留下接缝 |
| 极慢滚动（逐帧位移低于一个分析像素） | 已验证 | 长基线（帧 t−k 与 t）证据仍能拆出固定头部；`tests/unit/layers.test.ts`   |

## 不确定与缺口

| 需求                                                         | 状态               | 说明                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 无重叠跳转不编造距离                                         | 已验证             | `gap`：跳转观察成为独立片段，返回后回到原画布                                                                                                                                                                                                                                                          |
| 独立片段先无重叠跳转、再回访接回主画布，随后继续被回环闭合   | 已验证             | `tests/unit/layers.test.ts` 的 `geometry:` 用例：先 `FRAGMENT_ATTACHED` 整体接回，再对片段接回前后各自的历史区域都能 `LOOP_CLOSURE`，覆盖接回前后混合坐标系下的位置图修正                                                                                                                              |
| 大面积纯色无法判断运动                                       | 已验证             | `blank`：无纹理帧不画到任何位置，报 `UNOBSERVABLE_FRAME`                                                                                                                                                                                                                                               |
| 高度重复内容存在多个合理解                                   | 已验证（含不可解） | `repeated-list` 单向可解；`repeated-list-reversal` 像素级不可分辨，断言误差只能是行高整数倍并给出歧义警告                                                                                                                                                                                              |
| 推断区域给出 warning / confidence                            | 已验证             | 低置信、歧义、薄重叠、冲突、片段各有独立诊断码                                                                                                                                                                                                                                                         |
| 置信度是校准概率                                             | **否**             | 是启发式分数，文档与界面均声明                                                                                                                                                                                                                                                                         |
| **本轮发现的已知局限**：重复卡片内容中途反向时的周期别名歧义 | **已知局限**       | 在 1920×1082 / `analysisSize 480`（factor 4）测试中发现：重复排版内容中途反向滚动会让逐帧里程计落在相隔约一个周期的错误候选上；在可整除的 1080 高度和其他随机种子下同样复现，与分析因子是否整除无关，是运动匹配本身对周期性内容的歧义，不是本轮改动引入的回退。见 `tests/unit/layers.test.ts` 顶部注释 |

## 页面不是静态图片

| 需求                                                   | 状态   | 证据                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 固定顶栏 / 底栏 / 状态栏                               | 已验证 | 自动识别为固定层，边界定位到原像素；固定画布断言零冲突、像素一致                                                                                                                                                                                                                                                            |
| 闪烁光标、实时计数器、播放中的视频（页面坐标动态内容） | 已验证 | 动态连通块共同选择实际观察epoch；110/101/011不能拼成未出现的111。无共同完整观察时明确保留partial，全部原生候选与逐像素来源可导出；不做语义识别。                                                                                                                                                                            |
| 悬浮按钮、滚动条、鼠标指针、toast（屏幕/局部覆盖物）   | 部分   | 原有一致性投票之后，按最终pose顺序回放稀疏原生候选；竞争运动、外观身份与透明度证据决定可见性，静态区域可拼接不同干净来源。`floating`及专门Engine反例达到零可恢复污染；唯一干净帧与录制边界不再直接当作不可恢复。无可靠运动/外观区分或从未露出的区域仍保留不确定性；不能保证任意覆盖物都消失。具体当前计数与档案见测试产物。 |
| 页面留白边距不被误判为侧栏                             | 已验证 | 侧边带需自身有可见结构才成立                                                                                                                                                                                                                                                                                                |
| 动态区域语义识别                                       | **否** | 只做视觉变化区域处理，不识别“这是视频播放器”                                                                                                                                                                                                                                                                                |
| 整页来自同一时刻                                       | **否** | 不保证，冲突区域尽量取单一完整观察并记录来源帧                                                                                                                                                                                                                                                                              |

## 页面本身变化

| 需求                                                  | 状态         | 说明                                                                                                                                                                                                          |
| ----------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 懒加载图片出现                                        | 已验证       | `lazy-load`：两个版本都被接受，冲突被标记                                                                                                                                                                     |
| pinch zoom / 比例变化                                 | 部分         | `zoom`：识别出比例变化，保留独立片段并报告倍率；**不做跨缩放统一重建**。缩放检测按每个独立区域（pane）单独判定，不是整帧一个开关——整帧级判定会让一个 pane 的 pinch 把其他所有 pane 也一起判成缩放变化并片段化 |
| 地址栏收起改变可视区                                  | **已知局限** | `toolbar-collapse`：完成并报告冲突，错误像素 < 10%，不断言正确                                                                                                                                                |
| 录制中途尺寸 / 方向改变                               | 已验证       | `geometry-change`：保留前缀，状态 partial，报 `DECODE_PREFIX_ONLY`                                                                                                                                            |
| 通用非刚性 reflow、无限滚动改变高度、virtualized list | **否**       | 只有冲突检测、时间选择与独立片段等容错路径                                                                                                                                                                    |

## 内容类型

文字长文、图片、长条漫画、卡片 feed、重复列表、大面积空白、横向与二维内容都有对应场景。输入只有像素，没有 OCR 或语义模型。

## 运行环境

下段大型WebKit录屏的内存数字来自加入延迟来源回放之前的迁移验证，不能作为当前多候选流程的峰值。延迟来源流程的本次测试与成本见`test-results/full-scheme/`；真实移动设备仍需要单独验证。

Desktop Chrome 已实测（真实 Chrome，非 Playwright 自带 Chromium，后者没有 H.264）。Playwright WebKit（JSC + WebKit WebCodecs，UA 声明 Safari）也已实测跑通完整重建，包括较大的 HEVC 录屏（1920×1240、1152 帧、21.4 秒）：内存平稳（WebProcess 基线约 550 MB，跑完峰值 +~450 MB，Wasm 峰值 102–120 MB），能完整解码/重建/导出，也能在隐私浏览（临时会话）里跑完演示、把瓦片经 worker 读回、导出 PNG 与 ZIP、刷新后重新打开项目——但隐私浏览的 IndexedDB 只接受字节、拒绝一切 Blob，Blob 值（瓦片 PNG、帧参照）现在探测后自动降级为字节+MIME 存储；隐私浏览也没有 OPFS，导出改为内存中组装（上限 1 GB）并直接走浏览器下载。**真机 Safari（iPhone、iPad、真实 macOS Safari）全流程仍未验证**：已知的三处 Safari 特有差异是（1）Safari 不支持 `VideoFrame.copyTo({format:'RGBA'})`，不支持时改用逐帧核对过的 planar 路径（`copyTo()` 取原生 YUV 布局，核心按 libyuv 公式转 RGBA，首帧同时跑 canvas 比对通过才对整趟启用，否则退回 canvas 转换）；（2）macOS Safari 有独立于内存总量的后台内存回收阈值（页面不可见时门槛骤降），长时间处理放到后台可能被系统回收并重新加载页面——为此有崩溃记录器（`src/ui/flight.ts`）：页面线程每秒记录阶段/帧/内存/已用时间到 localStorage，页面被回收后下次打开会在诊断里给出 `PREVIOUS_RUN_INTERRUPTED`；（3）Playwright WebKit 2248（macOS，AVFoundation/CoreMedia 后端）实测无法解码 VP9 Profile 1（4:4:4 采样）：`VideoDecoder.isConfigSupported('vp09.01.20.08')` 直接返回不支持，与容器里声明的编解码字符串是否准确无关，真机 Safari 是否支持同样未验证。这些是从 Playwright WebKit 与用户报告的真机崩溃现象归纳出的证据，不等于真机已验证；细节见 [docs/history/2026-09-rust-migration-log.md](history/2026-09-rust-migration-log.md)。Android 全流程未验证。移动尺寸布局只做了 390×844 无横向溢出检查。

## 其他明确未实现

- 断点续算（可恢复已提交结果，不能从中断帧继续）。
- 跨片段的几何关系推断，除非回访给出可靠匹配（此时会整体接回并记录）。
- 兼容 seek 模式的逐帧覆盖保证：它是用户显式选择的近似路径，可能漏帧。
