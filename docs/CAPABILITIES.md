# 能力边界：逐项对应原需求

“已验证”指有带真值的自动化测试断言，或在真实 Chrome 中实际跑通并检查过输出。

## 移动与轨迹

| 需求 | 状态 | 证据 |
|---|---|---|
| 上下左右、斜向、非单调二维移动 | 已验证 | `traversal` `diagonal` `horizontal`：位置误差 0，缺失 0，虚构 0 |
| 停止、回滚、反复查看 | 已验证 | `revisit` 三次经过同一区域；`vertical` 含暂停与反向 |
| 轻微手抖、非恒定速度 | 已验证 | `vertical` `phone` 带抖动路径 |
| 高速 fling、内容只出现 1–2 帧 | 已验证 | `fling` `glimpse`：单帧可见内容仍进入结果 |
| 同一内容只出现一次 | 已验证 | 所有场景断言“虚构像素 = 0”且覆盖集合与观察视口并集相等 |
| 薄重叠跳转 | 部分 | 标记 `THIN_OVERLAP_STEP`；回访证据更强时改正并记录，此前像素可能留下接缝 |

## 不确定与缺口

| 需求 | 状态 | 说明 |
|---|---|---|
| 无重叠跳转不编造距离 | 已验证 | `gap`：跳转观察成为独立片段，返回后回到原画布 |
| 大面积纯色无法判断运动 | 已验证 | `blank`：无纹理帧不画到任何位置，报 `UNOBSERVABLE_FRAME` |
| 高度重复内容存在多个合理解 | 已验证（含不可解） | `repeated-list` 单向可解；`repeated-list-reversal` 像素级不可分辨，断言误差只能是行高整数倍并给出歧义警告 |
| 推断区域给出 warning / confidence | 已验证 | 低置信、歧义、薄重叠、冲突、片段各有独立诊断码 |
| 置信度是校准概率 | **否** | 是启发式分数，文档与界面均声明 |

## 页面不是静态图片

| 需求 | 状态 | 证据 |
|---|---|---|
| 固定顶栏 / 底栏 / 状态栏 | 已验证 | 自动识别为固定层，边界定位到原像素；固定画布断言零冲突、像素一致 |
| 悬浮按钮、滚动条、鼠标指针、toast、闪烁光标、实时计数器、播放中的视频 | 已验证 | `chrome-everything` 六种同时存在：主体轨迹误差 0，冲突区域被标记 |
| 页面留白边距不被误判为侧栏 | 已验证 | 侧边带需自身有可见结构才成立 |
| 动态区域语义识别 | **否** | 只做视觉变化区域处理，不识别“这是视频播放器” |
| 整页来自同一时刻 | **否** | 不保证，冲突区域尽量取单一完整观察并记录来源帧 |

## 页面本身变化

| 需求 | 状态 | 说明 |
|---|---|---|
| 懒加载图片出现 | 已验证 | `lazy-load`：两个版本都被接受，冲突被标记 |
| pinch zoom / 比例变化 | 部分 | `zoom`：识别出比例变化，保留独立片段并报告倍率；**不做跨缩放统一重建** |
| 地址栏收起改变可视区 | **已知局限** | `toolbar-collapse`：完成并报告冲突，错误像素 < 10%，不断言正确 |
| 录制中途尺寸 / 方向改变 | 已验证 | `geometry-change`：保留前缀，状态 partial，报 `DECODE_PREFIX_ONLY` |
| 通用非刚性 reflow、无限滚动改变高度、virtualized list | **否** | 只有冲突检测、时间选择与独立片段等容错路径 |

## 多滚动区域

| 需求 | 状态 | 证据 |
|---|---|---|
| 左右 pane 独立滚动 | 已验证 | `panes`：两条轨迹各自误差 0，分隔条定位到原像素 |
| 任意嵌套滚动容器 | **否** | 面积不足最大内容层 8% 的运动区域会被并入邻近区域 |
| 手动指定区域 | 已实现，未自动化验证 | 界面可画区域；覆盖优先级与未指定层有单元测试 |

## 内容类型

文字长文、图片、长条漫画、卡片 feed、重复列表、大面积空白、横向与二维内容都有对应场景。输入只有像素，没有 OCR 或语义模型。

## 输入、格式与解码

| 需求 | 状态 | 说明 |
|---|---|---|
| MP4 / MOV / fMP4 / WebM | 已验证 | 四种容器各 43 帧样本，Deno 与 Chrome 双端 |
| QuickTime / ReplayKit 有符号 `ctts` | 已验证 | 专门样本 + 真实 iOS 录屏解析测试；这是最初全部失败的根因 |
| B 帧、展示顺序、可变帧率、重复帧 | 已验证 | `vfr` 场景 + 容器样本断言时间戳单调且互异 |
| 不支持的编码 / 解码器错误 / 卡死 | 已验证 | 以假解码器注入，断言明确报错而非静默跳过 |
| 300MB+ / 10min+ 真实录屏完整重建 | **未验证** | 只验证了范围读取架构与真实 3456×2234 / 170 帧录屏 |
| HEVC / AV1 等 | 依运行时 | 启动前查询 `isConfigSupported`，不支持则明确报错 |

## 端侧运行与超大输出

| 需求 | 状态 | 说明 |
|---|---|---|
| 不把整个视频读入内存 | 已验证 | `BlobReader` 页面读取有单元测试，禁止 `arrayBuffer()` |
| 不保存所有解码帧 / 不建巨型 Canvas | 已验证 | 磁盘瓦片 + LRU，峰值驻留 ≤ 上限被每个场景断言 |
| 负坐标、巨大稀疏坐标 | 已验证 | 5200 万像素跨度的稀疏瓦片读写与淘汰测试 |
| 超尺寸输出分页 | 已验证 | 分页导出附世界坐标与 32px 重叠，不静默缩小 |
| 内存预算等于进程 RSS | **否** | 只约束自有瓦片缓存；解码器、GPU、浏览器缓存另计 |

## 运行环境

Desktop Chrome 已实测（真实 Chrome 153，非 Playwright 自带 Chromium，后者没有 H.264）。**Safari、iPhone、iPad、Android 全流程未验证**；移动尺寸布局只做了 390×844 无横向溢出检查。

## 其他明确未实现

- 断点续算（可恢复已提交结果，不能从中断帧继续）。
- 跨片段的几何关系推断，除非回访给出可靠匹配（此时会整体接回并记录）。
- 兼容 seek 模式的逐帧覆盖保证：它是用户显式选择的近似路径，可能漏帧。
